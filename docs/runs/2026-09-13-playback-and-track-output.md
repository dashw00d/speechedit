# Repeated speech and track output controls

## Reproduction

The corpus is the first 25 seconds of the owner's Staff Training – Final Pacing video, including “pay amounts throughout this video.” The transcript was generated by SpeechEdit's real browser Whisper worker. We also tested the actual shared VP8/Opus preview and collaborator MP3 downloaded from the matching review room, without modifying that room or its edits. Private media and transcript artifacts remain outside the repository.

The playback test mounts the real Monitor and Timeline, decodes actual media in Chromium, and captures mixed output on the audio thread using an AudioWorklet. A 300 ms UI task every 600 ms reproduces a busy editor/background scheduling delay. Audio continues advancing while RAF is delayed. The previous clock logic compared audio against a wall-clock increment capped at 80 ms, then repeatedly sought backward to that stale time. The original implementation audibly repeated speech and took roughly 50 seconds to play a 25-second recording.

The UI now follows forward audio progress within the current retained segment. It still respects explicit seeks, cuts, loops, source changes, and short-recording EOF silence. The same load test completes in 25.01 seconds with zero backward seeks. The captured output transcribes to the expected speech, including the reported phrase. Ordinary playback and sequential owner/collaborator replacement also finish in approximately 25 seconds with zero backward seeks.

## Track controls

The eye excludes a track from preview and export. Every track keeps its timeline row, label, clips, order, and controls. Disabled rows are 32 px high with gray clips; toggling the same eye restores their usual height. Primary Picture now renders black when hidden; primary Voice is silent when hidden or muted. Overlays, captions, and additional audio retain their existing output exclusions. Duration and edit positions do not change.

The browser check clicks the actual eye buttons for Picture, Voice, Graphics, and Captions. Their heights change from 50/46/38/38 px to 32 px and back, with the rows and clips retained. The gray disabled Graphics row was also visually inspected. Unit checks verify the shared preview/export graph and unchanged duration/content.

## Running with a private corpus

`SPEECHEDIT_SPEECH_CORPUS` points to a local directory containing:

- `source.mp4`: a 25-second real speech video.
- `shared.webm`: its shared VP8/Opus preview.
- `replacement.mp3`: a 4.56-second voice replacement (shorter decoded content is covered by the EOF regression).
- `transcript.log`: JSON output from `SPEECHEDIT_WHISPER_AUDIO=<source audio> bun run smoke:whisper <local server URL>`; use the actual timestamped `cues`.

Run `bun run smoke:real-speech --no-sandbox` and `bun run smoke:track-visibility --no-sandbox` with that environment variable. `SPEECHEDIT_CASES=loaded` runs just the busy-editor regression. Captured WAVs and the track screenshot are written to the corpus directory. No media is uploaded by these tests. The test fails on backward seeks or a duration mismatch over one second; transcripts alone are insufficient because speech recognition can conceal repetitions.

Validation: 758 tests passed, TypeScript checks, theme guard, web and desktop builds. The existing short-recording EOF/replay smoke is also retained. Deployment must preserve `Permissions-Policy: microphone=(self)`; ServerChirp regenerates this header, so verify it after deploying.
