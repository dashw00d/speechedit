1. **Extreme Power, Extreme Convenience**
   The system should be capable enough for experts while remaining simple enough that a child could accomplish common tasks without training. Complexity belongs underneath the interface, not in front of the user. Powerful defaults, guided actions, automation, and progressive disclosure should eliminate unnecessary decisions.

2. **Context Before Navigation**
   Put relevant actions, options, explanations, and next steps where the user is already working. Users should not constantly leave their task to hunt through toolbars, menus, or settings. The full configuration surface should still exist, but common actions should come to the user when they become relevant.

3. **Progressive Depth**
   Start simple, reveal depth on demand. The first interaction should expose the few choices that matter most. Advanced controls, detailed settings, keyframes, rules, automation, and configuration should remain accessible without dominating the default experience.
   **Simple first, limitless underneath.**

4. **Modular by Default**
   Features should be extendable, hookable, composable, and independently replaceable whenever practical. New tools should plug into shared primitives rather than create isolated systems. A feature should ideally be usable by the UI, automation, AI, plugins, shortcuts, and future workflows without being rewritten.

5. **One Capability, Many Surfaces**
   A feature should not be tied to a single button. The same underlying action may appear contextually, in the inspector, command palette, keyboard shortcut, automation system, or AI interface. The implementation belongs in one place; the interface can surface it wherever useful.

6. **Centralized Visual Language**
   Styling should come from a centralized design system: typography, spacing, color, elevation, motion, icons, control states, component behavior, and accessibility rules. Individual features should not invent their own visual language. Changing the design system should propagate predictably throughout the application.

7. **Flexible Workspace, Stable Product**
   The interface should adapt to the user rather than forcing one permanent layout. Panels, inspectors, transcript, timeline, preview, media browser, and analysis tools should be movable, collapsible, resizable, hideable, and eventually saveable as workspaces. Customization should not compromise consistency or make the app impossible to understand.

8. **Explain Consequences, Not Machinery**
   Users should understand what an action will do without needing to understand how it is implemented. Prefer:
   **“Remove this pause. Saves 4.8 seconds and closes the gap.”**
   over technical controls and terminology unless the user asks for them. When something has consequences, explain them clearly and locally.

9. **Automation Must Remain Inspectable**
   AI and automatic tools should accelerate decisions, not take ownership away from the user. Automated edits should be reversible, previewable, understandable, and preferably represented through the same normal editing operations a human uses. Confidence and uncertainty should be visible where relevant.

10. **Make the Next Step Obvious**
    Good software should reduce the amount the user must remember. After an action, surface likely next actions when useful. Empty states should teach. Errors should offer recovery. Contextual helpers should guide without becoming a rigid wizard.

11. **Consistency Beats Cleverness**
    Similar actions should behave similarly everywhere. Selection, undo, preview, confirmation, dragging, keyboard behavior, contextual menus, inspectors, and destructive actions should follow predictable rules. Novel interaction is worthwhile only when it is materially better than an established pattern.

12. **Customization Without Fragmentation**
    Users can customize layout, defaults, workflows, shortcuts, styles, and automation, but customization should operate through shared systems rather than forks and special cases. The application should remain coherent even when heavily personalized.
